# Offline controller and predictor readiness audit

Reassemble and verify the Zephyrus handoff as directed by `docs/evidence/cloud-handoff-20261004-archive/README.md`, then run `PYTHONPATH=. python3 tools/evaluate_exported_predictor.py` from the repository root to regenerate `predictor-report.json`. The command reads only published benchmark and quality records. It checks the two exported report checksums, the LFM content address, each manifest identity, all 30 indexed benchmark results using the repository's validator, and all 34 handoff-file sizes and checksums. It does not run model inference or consume held-out quality examples.

The current ridge predictor was fitted on the 20 Qwen3/Qwen3.5 rows and frozen before checking the ten LFM rows. Mean absolute percentage error was 25.58% on Qwen3, 19.21% on Qwen3.5, and **109.85% on LFM**; worst LFM error was 161.75%. These errors are on aggregate fixed-tape RTL cycles. The current predictor does not generalize adequately to the held-out model, so its estimates cannot support a claimed controller improvement or automatic promotion.

The Zephyrus handoff supplies matching balanced INT8 quality approval for each model. The existing controller correctly retains balanced in all six short-workload comparisons and excludes the other three personalities, which lack matching quality approval. In a **performance-only shadow comparison**, compute is fastest on all six tapes: its advantage over balanced is 0.30–0.31% for Qwen3, 2.54–2.98% for Qwen3.5, and 0.23–0.26% for LFM. The predictor ranks compute first on all six, but that ranking does not override its large held-out absolute error or the quality gate. Reported break-even overhead values are hypothetical thresholds for repeated identical tapes, not measured switch costs.

Exact DRAM/TMEM checks in the 30 performance runs establish execution correctness for those tapes; they do not grant all four personalities model-quality approval. The published data also lack sequential request episodes and measured program/reload/re-prefill costs. Controller training or promotion through the repository's gated release path therefore remains unrun here. A simulation using invented zero switching costs would not close this gap.

Subsequent cloud work completed the nine missing ISA validation checks; all passed with matching benchmark identities. See `../personality-validation-20261005/`. Their `selectable` fields are false because the release contract requires untouched held-out approval for each exact configuration. The consumed balanced held-out evaluations were not repeated. Next, establish that approval path, export verified episodes with measured program/reload/re-prefill costs, and evaluate predictor alternatives on the same frozen Qwen3/Qwen3.5 to LFM split. Then compare fixed, heuristic, predictor-only, budget-matched random, and five seeded Double DQN policies. Retain the deterministic controller if the non-regression gate fails.

No physical timing, power, or deployed FPGA behavior is inferred from this audit.
