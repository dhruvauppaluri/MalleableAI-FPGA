# Run the single-projection Qwen3 screen on Zephyrus

This is the local Windows/WSL handoff for the development test requested
after shared-matrix attempt 04. It checks whether copying only `gate_proj`
or only `up_proj` from Qwen3 layer 12 to layer 13 preserves the pretrained
model's predictions better than copying both. It does not train a model,
evaluate a release held-out suite, repeat the consumed 27-pair screen, or
change automatic program switching.

## 1. Install or open Ubuntu under WSL2

If Ubuntu is not installed, update the NVIDIA **Windows** driver first. Then
open PowerShell as Administrator and run:

```powershell
wsl --install -d Ubuntu-24.04
```

Restart if prompted. Open Ubuntu and create a Linux user. The Windows driver
provides GPU access to WSL; do not install a Linux NVIDIA display driver in
Ubuntu. See the [Microsoft WSL guide](https://learn.microsoft.com/windows/wsl/install)
and [NVIDIA CUDA on WSL guide](https://docs.nvidia.com/cuda/wsl-user-guide/index.html).

If WSL is already present, inspect it from Windows Terminal or PowerShell:

```powershell
wsl -l -v
wsl
```

Ubuntu must show version `2`. The second command opens the default distro;
if that is not Ubuntu, run `wsl -d Ubuntu-24.04` instead, using the exact name
shown by `wsl -l -v`. All commands below run in Ubuntu, not PowerShell.

In Ubuntu, install Git and Python's virtual environment support, then check
that Windows has exposed the GPU:

```sh
sudo apt-get update
sudo apt-get install -y git python3 python3-venv python3-pip
nvidia-smi
```

If `nvidia-smi` fails, fix the Windows driver/WSL connection before proceeding.

## 2. Make an isolated checkout

If the project is absent, clone it into Ubuntu's Linux filesystem:

```sh
mkdir -p /home/dhruv/projects
git clone --branch codex/policy-correction \
  https://github.com/dhruvauppaluri/MalleableAI-FPGA.git \
  /home/dhruv/projects/MalleableAI-FPGA
```

Replace `/home/dhruv` throughout this guide with your actual Ubuntu home
directory if your Linux username differs. Keep the checkout under Ubuntu's
home directory, not `/mnt/c`. If the checkout already exists, do not clone
over it. Fetch the review branch and make a separate worktree so local edits
and ignored model weights stay untouched:

```sh
git -C /home/dhruv/projects/MalleableAI-FPGA fetch origin codex/policy-correction
git -C /home/dhruv/projects/MalleableAI-FPGA worktree add --detach \
  /home/dhruv/projects/MalleableAI-FPGA-projection-screen \
  origin/codex/policy-correction
cd /home/dhruv/projects/MalleableAI-FPGA-projection-screen
```

If the worktree path already exists, inspect it first; do not overwrite or
reuse a previously claimed screen. The source must contain
`tools/screen_shared_matrix_projections.py` with SHA-256
`f6355b6476464ea2d51e250ee9ca482e03aef5c824abb15f61a1500baf6da72c`.

## 3. Check the CUDA runtime and pinned model

If the original checkout has no `.venv`, create one and install CUDA PyTorch
using the command generated by the [official PyTorch selector](https://pytorch.org/get-started/locally/)
for **Linux / Pip / Python / CUDA** and your Windows driver. Then install the
remaining packages:

```sh
cd /home/dhruv/projects/MalleableAI-FPGA
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
source .venv/bin/activate
# Paste the CUDA PyTorch command from the official selector here, while activated.
.venv/bin/python -m pip install 'transformers>=4.57,<5' 'datasets>=3,<5' safetensors
cd /home/dhruv/projects/MalleableAI-FPGA-projection-screen
```

If `.venv` already exists, leave it in place. Never replace a working CUDA
wheel with a CPU wheel. Use the original project's Python environment and
model cache:

```sh
PAIR_SCREEN_PYTHON=/home/dhruv/projects/MalleableAI-FPGA/.venv/bin/python
PAIR_SCREEN_MODEL=/home/dhruv/projects/MalleableAI-FPGA/build/models/Qwen3-0.6B
"$PAIR_SCREEN_PYTHON" -c 'import torch, transformers; assert torch.cuda.is_available(), "CUDA unavailable"; print("GPU:", torch.cuda.get_device_name(0), "VRAM GiB:", round(torch.cuda.get_device_properties(0).total_memory / 1024**3, 1), "Transformers:", transformers.__version__); print(torch.ones(1, device="cuda") + 1)'
```

If the pinned model is absent, download **only** Qwen3-0.6B from the frozen
repository revision, not all three project models:

```sh
"$PAIR_SCREEN_PYTHON" tools/download_llm_models.py \
  --destination /home/dhruv/projects/MalleableAI-FPGA/build/models \
  --only Qwen3-0.6B
```

Check the script and model bytes before the run:

```sh
echo 'f6355b6476464ea2d51e250ee9ca482e03aef5c824abb15f61a1500baf6da72c  tools/screen_shared_matrix_projections.py' | sha256sum -c -
echo 'f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b  /home/dhruv/projects/MalleableAI-FPGA/build/models/Qwen3-0.6B/model.safetensors' | sha256sum -c -
```

Stop if a check fails. The script also checks the checkpoint's config and
tokenizer hashes before it claims a run. The previously published 0→1 and
12→13 attempts use this same pinned checkpoint. A 5070 Ti with 12 GiB or
more VRAM should have room for this **single-model forward-only** screen;
the command prints the actual VRAM before execution.

## 4. Prepare the exact development corpus

The Radeon development text was not committed to Git. Recreate it locally
using the existing opt-in helper. The screen refuses a different dev file or
token sequence, so a changed upstream revision cannot silently alter the
comparison.

```sh
"$PAIR_SCREEN_PYTHON" -c 'import datasets'
"$PAIR_SCREEN_PYTHON" tools/prepare_shared_matrix_text.py \
  --output-dir build/shared-matrix-text-projection-01
echo 'ec4a17fa316b6dbdb4448aa3681ee6779f79bfbbb3ba090a2b5155cd52ff12  build/shared-matrix-text-projection-01/dev.jsonl' | sha256sum -c -
```

If only the `import datasets` line fails, install the bounded dependency into
that same virtual environment with
`"$PAIR_SCREEN_PYTHON" -m pip install 'datasets>=3,<5'`, then run this step again.
The helper may cache public WikiText split files; the screen scores only
the frozen development tokens. No release held-out suite is opened.

## 5. Run the bounded CUDA screen once

```sh
set +e
set -o pipefail
timeout --signal=INT --kill-after=10s 3m \
  "$PAIR_SCREEN_PYTHON" -u tools/screen_shared_matrix_projections.py \
  --model "$PAIR_SCREEN_MODEL" \
  --dev-jsonl build/shared-matrix-text-projection-01/dev.jsonl \
  --output-dir build/shared-matrix-projection-screen-01 \
  2>&1 | tee build/shared-matrix-projection-screen-01.console.log
printf 'screen_exit_status=%s\n' "${PIPESTATUS[0]}"
```

The script exclusively claims `build/shared-matrix-projection-screen-01`,
scores the unchanged model, then gate-only and up-only copies, restoring
weights after each. It writes `result.json` only when both finish. A claimed
directory is consumed even if the run times out or fails; never rerun into
the same directory. Do not run the previous all-27-pair screen again.

## 6. Save and share the result

```sh
cat build/shared-matrix-projection-screen-01/result.json
tar -czf build/shared-matrix-projection-screen-01-evidence.tar.gz \
  -C build shared-matrix-projection-screen-01 \
  shared-matrix-projection-screen-01.console.log \
  shared-matrix-text-projection-01/corpus-manifest.json
explorer.exe build
```

The last command opens the worktree's `build` folder in Windows Explorer.
Upload the small `.tar.gz` to the Codex chat. Keep the checkpoint and JSONL
text files out of Git. If `result.json` is missing, upload the claim,
progress, failure file if present, and console log instead. The frozen
selection rule requires teacher agreement >=90% and NLL increase <=5%
on these development tokens; among eligible panels it picks the higher
teacher agreement, then lower NLL. A selected panel is only a candidate
for a new matched Radeon training attempt. Training must use a fresh freeze
and output root, and its own Radeon quality checks must pass before any
independent held-out evaluation.
